# Service Bay Scheduler Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go service for `POST /appointments`, `GET /appointments/{id}` and `GET /availability` that behaves exactly as the booking spec says, with Postgres as the final guard against overlapping bookings.

**Architecture:** There are three layers plus two leaf packages:
- `handler` covers decoding, 400 checks, status mapping and middleware.
- `service` covers check order, assignment, the retry loop and availability. It declares the `Repository` interface.
- `repository` covers SQL, transactions, and mapping constraint names to typed errors.
- `model` holds types, errors, the `Clock` interface and the pure rules. `clock` holds the system and fixed clocks.

Imports are `handler → service → model` and `repository → model`. Neither `service` nor `model` imports `net/http`, `pgx` or `database/sql`, and `repository` never imports `service`. Because of that, the transaction travels in the `context` (`InTx(ctx, func(ctx) error)`), not as a `service` type. Spec examples run end to end through the real handler, service and repository, inside a test transaction that is rolled back afterwards.

**Tech Stack:** Go 1.24 (`net/http` method patterns, `log/slog`), `github.com/jackc/pgx/v5` (+ `pgxpool`, `stdlib` for goose), `github.com/pressly/goose/v3` (embedded SQL migrations), `github.com/prometheus/client_golang`, Postgres 16 in Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-20-booking.md`. Also read `docs/design.md`, `docs/decisions.md` (D-numbers) and `openapi.yaml`. Spec and design are frozen. If this plan disagrees with them, they win.

## Global Constraints

- Module path: `github.com/vumanhcuongit/service-bay-scheduler`. Go `1.24`.
- Layers: `handler → service → model` and `repository → model`. `clock` imports nothing internal. `make layers` (added in Task 3) fails if any of these prints a line:
  - `go list -deps ./internal/model ./internal/service | grep -E '^(net/http|database/sql)$|jackc|internal/(handler|repository)'`
  - `go list -deps ./internal/repository | grep -E 'internal/(service|handler)'`
  - `go list -deps ./internal/handler | grep -E 'jackc|internal/repository'`
- Nothing calls `time.Now()` except `clock.System` and latency timing in middleware.
- Check order: 400 → idempotency key lookup → 404 → 422 → 409 (spec rule 7).
- 409 reasons, first failure wins: `vehicle_busy` → `no_bay` → `no_technician`.
- Retry: at most 3 attempts in total on `ErrBayTaken`/`ErrTechnicianTaken`, with a random backoff of 50–100 ms before each retry. Then 503 with `Retry-After: 1` and nothing stored.
- Exclusion constraints are named `appointments_bay_excl`, `appointments_technician_excl` and `appointments_vehicle_excl`. Each is `WHERE (status = 'confirmed')` and needs `btree_gist`.
- All times in responses are UTC, RFC 3339, e.g. `2026-10-21T02:00:00Z`.
- Error bodies are `{"message": "..."}`. 409 bodies are `{"reason": "...", "message": "..."}`.
- Metrics are `booking_attempts_total{result}` with result ∈ `created|replayed|conflict|invalid|unavailable|error` (400/404/422 = `invalid`), and the histogram `booking_latency_seconds`.
- Test clock default is `2026-10-20T12:00:00+07:00`. "Day" is `2026-10-21`, local `+07:00`.
- Commit after each task: `feat: <summary>` for code, `docs: <summary>` for docs only, and `ci: <summary>` for CI workflow and its Makefile targets.
- Naming, repository interface (in `service`): the verb prefix states the contract. `Get<X>(ctx, id)` returns one row, or `model.ErrNotFound` if it is missing. `List<X>(ctx, …)` returns many rows, and an empty slice is not an error. `<X>Has<Y>` / `Exists` return bool. Writes are `Insert` / `Save` / `Claim`, and the name says what the write does: `GetDealership, GetVehicle, GetServiceType, GetAppointment, ListBays, ListQualifiedTechnicians, ListBusy, VehicleHasOverlap, ClaimKey, SaveKeyOutcome, InsertAppointment`. Plain nouns stay for struct fields in `model` (`a.Start`, `d.Location`).
- Naming, service: one method per use case, named as the business action, not as CRUD: `Book(ctx, req, key) (Outcome, error)`, `GetAppointment(ctx, id) (Appointment, error)`, `ListAvailability(ctx, dealershipID, serviceTypeID, date) ([]time.Time, error)`.
- Naming, handler: one unexported func per route, `handle<Verb><Resource>`: `handleCreateAppointment, handleGetAppointment, handleGetAvailability`. Helpers are `decodeBookingRequest, writeJSON, writeError`. Middleware is `requestID, requestTimeout, accessLog, metrics`.
- Naming, model pure functions: predicates read as yes/no questions, actions as verbs: `IsAligned(t), Overlaps(a, b), LocalWindow(...), PickResources(...), HashRequest(req)`.
- Naming, typed errors: `Err<What>` for sentinels (`ErrNotFound, ErrBayTaken, ErrTechnicianTaken, ErrVehicleBusy, ErrUnavailable`), `<What>Error` for structs (`NotFoundError{What, ID}, InvalidError{Message}`).
- CI: `.github/workflows/ci.yml` runs on push and pull_request against a `postgres:16` service. It runs `go vet ./...`, golangci-lint (default config, `v2.15.0`) and `make test`. `make ci` runs the same three locally (`vet`, `lint`, `test`). `make lint` uses `go run` with the same pinned version, so it needs no local install. Every task must leave `make ci` green.
- Fixes found in the user's review are committed as `fix(ai): <what was wrong, how it was caught>`.
- Execution: native. Stop after each task and show the diff before starting the next one.

## Review Focus

These are inputs the spec implies but none of its examples cover. Each one has a test in the task that owns the code.

1. **Malformed JSON body** (`[]`, `{"dealership_id":`, trailing data, body > 1 MiB) → 400. It must not panic or return 500. *Task 4.*
2. **`GET /appointments/{id}` with a non-UUID id** (`/appointments/abc`) → 400, as `openapi.yaml` requires. It must not reach Postgres and return 500 on a uuid cast. *Task 3.*
3. **The same `Idempotency-Key` in upper and lower case** is the same key and replays. The `uuid` column type normalises it. *Task 6.*
4. **A key row older than 24 h** with a different payload runs as new (201), not 422 (spec §6). *Task 6.*
5. **Bad `GET /availability` parameters**: missing `date` or `date=2026-13-01` → 400; `dealership_id=DL9` → 404; `service_type_id=TIRE` for DL1 → 422. *Task 8.*

type Appointment struct{ ID, DealershipID, CustomerID, VehicleID, ServiceTypeID, BayID, TechnicianID string; Start, End time.Time; Status string }
type Reason string // ReasonVehicleBusy="vehicle_busy", ReasonNoBay="no_bay", ReasonNoTechnician="no_technician"
type Conflict struct{ Reason Reason; Message string }
type Outcome  struct{ Appointment *Appointment; Conflict *Conflict; Replayed bool } // exactly one of Appointment/Conflict
type StoredKey struct{ Hash string; Outcome Outcome }
type NotFoundError struct{ What, ID string } // Error() = "<what> <id> not found", What ∈ dealership|vehicle|service type|appointment
type InvalidError  struct{ Message string }
var ErrNotFound, ErrUnavailable, ErrBayTaken, ErrTechnicianTaken, ErrVehicleBusy error // errors.New sentinels
// clock.go
type Clock interface{ Now() time.Time }
// slots.go
const Slot = 15 * time.Minute
func IsAligned(t time.Time) bool                                 // t.Unix()%900 == 0 && t.Nanosecond() == 0
func Overlaps(a, b Interval) bool                                // half-open: a.Start < b.End && b.Start < a.End
func LocalWindow(loc *time.Location, day time.Time, from, to time.Duration) (time.Time, time.Time) // day's Y-M-D in loc
func PickResources(bays []string, techs []Technician, busy []Busy, loc *time.Location, start, end time.Time) (bayID, techID string, reason Reason)
// hash.go
func HashRequest(r BookingRequest) string
```

`PickResources` sorts copies of `bays` and `techs` by id. The first bay with no overlapping `busy` entry wins, and if there is none it returns `ReasonNoBay`. Then the first technician whose `LocalWindow(loc, start, WorkStart, WorkEnd)` contains `[start,end)` and who has no overlapping `busy` entry wins, and if there is none it returns `ReasonNoTechnician`. `techs` are already qualified (filtered by skill in the repository). The reason is `""` on success. Both booking and availability use this one function (spec rule 12).

`HashRequest` returns the hex SHA-256 of `json.Marshal` of a struct with the fixed field order `dealership_id, service_type_id, start, vehicle_id`, where `start = r.Start.UTC().Format(time.RFC3339)`.

```

`Repository` keeps the current tx under an unexported context key. A private `r.q(ctx) DB` returns that tx, or `r.db` if there is none. `InTx` calls `r.q(ctx).Begin(ctx)`, so a nested call or a test tx becomes a savepoint, then passes `context.WithValue(ctx, txKey{}, tx)` to `fn`. The spec env passes the test `pgx.Tx` as the `DB`, so nothing escapes `t.Cleanup`'s rollback.

`InsertAppointment` maps `*pgconn.PgError` with Code `23P01` by `ConstraintName`: `appointments_bay_excl` → `ErrBayTaken`, `appointments_technician_excl` → `ErrTechnicianTaken`, `appointments_vehicle_excl` → `ErrVehicleBusy`. Other errors are wrapped as they are.

`Book` in this task: open `InTx` → `GetDealership` → `GetVehicle` → `GetServiceType` → `VehicleHasOverlap` → `ListBusy(dealership, [start,end))` + `ListBays` + `ListQualifiedTechnicians` → `PickResources` → insert with `CustomerID = vehicle.CustomerID`, `End = Start + Duration`, `Status = "confirmed"`. Each 409 message names local times, e.g. `no qualified technician free for 09:00–10:00` (openapi example).

Handler status mapping in this task:
- `Outcome.Appointment` → 201 with the appointment JSON.
- `Outcome.Conflict` → 409.
- `*model.NotFoundError` → 404.
- Anything else → 500 `{"message":"internal error"}`, plus a log line.

A branch is added only with the task whose tests produce it: Task 5 adds `*model.InvalidError` → 422, and Task 7 adds `model.ErrUnavailable` → 503 + `Retry-After: 1`.

Request-id middleware: take `X-Request-ID` or generate 16 random bytes as hex with `crypto/rand`, set it on the response, and store it in the context.

`GET /appointments/{id}`: if `id` doesn't match the UUID regex `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$` → 400, before calling the service (Review Focus 2).

`main`: env `DATABASE_URL` and `ADDR` (default `:8080`), `slog.NewJSONHandler(os.Stdout)`, `clock.System{}`, `http.Server` with `ReadHeaderTimeout: 5s`. On SIGINT/SIGTERM, `Shutdown` with a 10 s timeout (D12).

### Task 6: Idempotency keys

**Files:**
- Modify: `internal/repository/writes.go`, `internal/service/booking.go`, `internal/handler/decode.go`, `internal/handler/handler.go`
- Test: `spectest/idempotency_test.go`

**Interfaces:**
- `ClaimKey` inserts the key first, waits on a concurrent holder, and returns the stored row when it is fresh:

```sql
INSERT INTO idempotency_keys (key, request_hash, created_at) VALUES ($1, $2, $3)
ON CONFLICT (key) DO UPDATE
   SET request_hash = EXCLUDED.request_hash, status = NULL, body = NULL, created_at = EXCLUDED.created_at
   WHERE idempotency_keys.created_at < $3 - interval '24 hours'
RETURNING key
```

  A returned row means the key was claimed, so `ClaimKey` returns `nil`. No row means a fresh committed row exists, and the conflicting row is now locked. Then `SELECT request_hash, status, body` and return `&model.StoredKey{Hash, Outcome}` (unmarshal `body` into `Outcome`). `$3` is the service clock's `now`, not `now()`.
- `SaveKeyOutcome` sets `status` (`created`|`conflict`) and `body = json(Outcome)`.
- Handler: `Idempotency-Key` present and not matching the UUID regex → 400. This happens in decode, so it comes before any lookup (N22, N23).

`Book` with key: inside `InTx`, `ClaimKey(key, HashRequest(req), now)` runs first.
- Stored and hash equal → return the stored `Outcome` with `Replayed = true`. No further checks run (M18).
- Stored and hash differs → `&model.InvalidError{"Idempotency-Key reused with a different payload"}`.
- Otherwise run the 404/422/409 checks. A 201 or 409 calls `SaveKeyOutcome` before `fn` returns nil, so both commit together. 404/422 return an error, so the key row rolls back with them.

**Interfaces:**

- Produces (test-only): `type flakyRepo struct{ service.Repository; failures int; err error; inserts int }`. The retry loop is in `Book` around `InTx`:
- `errors.Is(err, model.ErrBayTaken|model.ErrTechnicianTaken)`: if `attempt < 3`, log `result=retry attempt=n`, sleep `50ms + rand.N(50ms)` (`math/rand/v2`, respect `ctx.Done()`), and run again. After 3 attempts → `model.ErrUnavailable`.

A 23P01 only happens after the other booking committed, so the fresh check normally returns 409 `vehicle_busy` and stores it on the key row through the normal path (D8: no further candidates are tried).
- If that re-run returns `model.ErrVehicleBusy` again, return `Outcome{Conflict: vehicle_busy}` without storing it. Never 500 (design §4).
